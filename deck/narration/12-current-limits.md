There are some known constraints. You can't reverse a payment because the Inio public API doesn't expose the payment allocation identifiers needed for reversals. We deferred invoice creation because new invoices go directly to end customers, which is too risky for AI-driven workflows. Some AI assistants, including Claude, won't send social security numbers, so creating consumer customers may need the back office. We've also documented some upstream API bugs in Jira. Single invoice status filters return HTTP 500 errors, and pagination on retry attempts is ignored. These are limitations we're tracking with the API team.
