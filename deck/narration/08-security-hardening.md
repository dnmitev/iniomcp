We ran an independent security audit that found 29 issues across seven root causes. Version 0.4.0 fixed the critical ones. Before, an unauthenticated client could force the server to consume four megabytes of memory per request. Now we reject bad requests before reading the body. We also fixed eight of the eleven write tools that were incorrectly reporting successful writes as failures, which could have led to duplicate operations. Request bodies are capped at 256 kilobytes. Malformed requests are handled before authentication runs. The audit made the server significantly more secure.
