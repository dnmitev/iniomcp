<objective>
## Goal
Make the PROJECT.md claim "accepted writes never reported as failed; uncertain outcomes tell the model to check before retrying" true for all 11 write tools, not 3 of them:
1. Uncertain: the client appends the check-before-retry suffix to every non-GET failure with status 0 **or ≥ 500**. Today it covers only status 0 (timeout, network) and unreadable 2xx; a 5xx gets no hint unless the tool adds one.
2. Accepted: when a write POST/PATCH resolves (2xx) but its answer is unreadable, either because the client could not parse the envelope or because the tool's own shape check fails, the tool returns `ok` with a note to check before retrying. It never returns `fail`.

## Purpose
AEGIS F-04-002 (medium; absorbs F-00-003): 8 of 11 write tools can report a landed write as failed, and 9 give no hint on 5xx. A model that sees "failed" retries, and for payments, credits and stage resets a retry duplicates money movements or distributions. Closes R5.

## Output
- `src/inio-client.ts`: 5xx on non-GET carries `uncertainOutcome`, whether or not the body is a JSON error envelope.
- `src/tools/result.ts`: one shared helper for "write accepted, answer unreadable" (`ok` + note). The existing `isUnreadableSuccess` is reused.
- All 11 write tools route unreadable-2xx and failed shape checks through that helper.
- `create-payment` and `create-customer`: keep only their tool-specific "how to check" pointer (get_invoice remainingAmount, get_customer by number) after the client's generic sentence, so the "may or may not" sentence does not appear twice.
</objective>

## AC-1: 5xx on a write carries the check-before-retry hint
```gherkin
Given INIO_ALLOW_WRITES=true
When any POST or PATCH to the Inio API answers 500, 502 or 503, with a JSON error envelope or without one
Then the tool result is an error whose text includes the API code and message (as today) followed by "The change may or may not have been applied; check before retrying."
And a GET answering 5xx carries no such sentence
And a 4xx write error carries no such sentence
```

## AC-2: Timeouts and network errors unchanged
```gherkin
Given a write that times out or cannot reach the API (status 0)
When the tool returns
Then the text still includes the check-before-retry sentence exactly once
```

## AC-3: Accepted write with an unreadable answer is success plus a note, in every write tool
```gherkin
Given a write tool whose POST/PATCH answered 2xx
When the answer has no readable result envelope (client-level) or fails the tool's shape check (tool-level)
Then the tool returns a non-error result containing a note that the change was accepted but the answer could not be read, and to check before retrying
And this holds for all 11 write tools: create/update/cancel customer pause, update_invoice_due_date, update_invoice_stop_until_dates, update_customer, reset_invoice_stage, match_credit_invoice, create_credit_invoice, create_payment, create_customer
```

```gherkin
And "may or may not" appears exactly once
```
