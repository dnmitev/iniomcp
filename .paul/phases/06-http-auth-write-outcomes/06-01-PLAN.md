<objective>
## Goal
In HTTP mode, reject unauthenticated and wrong-path requests before any body byte is buffered. Cap the request body well below the SDK's 4 MiB default. Warn at startup when the server listens on a non-loopback host. Let in-flight requests finish on shutdown instead of cutting every connection at once.

## Purpose
AEGIS F-04-007 (medium, reproduced): `toNodeHandler` converts the Node request into a web `Request`, buffering up to 4 MiB, before `handle` checks the bearer token. Unauthenticated clients can therefore push the process RSS from 96 to 531 MB. This also makes the security-engineer's "auth runs before the SDK sees the body" statement (D-007) true in code. Closes R4: F-04-007, F-04-004, F-01-006.

## Output
- `src/http.ts`: path and bearer checks on the Node `IncomingMessage` before `nodeHandler`; `maxRequestBodySize`; drain-then-close shutdown.
- `src/index.ts`: startup warning for non-loopback hosts.
- `test/unit/http.test.ts`: new tests for each AC.
</objective>

<acceptance_criteria>

## AC-1: Unauthenticated requests are rejected before the body is read
```gherkin
Given the HTTP server is running with a bearer token
When a client POSTs a 1 MiB body to /mcp with no Authorization header, a malformed one, or a wrong token
Then it receives 401 with `WWW-Authenticate: Bearer`
And the body stream is never consumed: the request handler resolves the response without waiting for the upload to finish, and the connection is closed afterwards
And the token comparison is still the constant-time SHA-256 digest compare
```

## AC-2: Wrong paths are rejected before the body is read
```gherkin
Given the HTTP server is running
When a client sends any request to a path other than /mcp (with or without a body, with or without a valid token)
Then it receives 404 without the body being read
```

## AC-3: Authenticated bodies are capped
```gherkin
Given a client with the valid bearer token
When it POSTs a body larger than 256 KiB to /mcp
Then it receives 413 and the MCP handler is not called
And a normal initialize and tools/call round trip still succeeds
```

## AC-4: Non-loopback bind is visible at startup
```gherkin
Given HOST is not 127.0.0.1, localhost or ::1 (for example 0.0.0.0 in the Docker image)
When the server starts in HTTP mode
Then a single warn-level log line names the host and says the bearer token is the only barrier
And no warning is logged for loopback hosts or in stdio mode
```

## AC-5: Shutdown drains before forcing
```gherkin
Given an authenticated request is in flight
When the process receives SIGTERM or SIGINT
Then the server stops accepting new connections, closes idle ones, and lets the in-flight request finish
And the remaining connections (for example open SSE streams) are forced closed after a grace period shorter than the existing 2 s hard exit
And the existing shutdown tests (single, double and mixed signals; exit 0; one "server stopped" line) still pass
```

## AC-6: Existing behaviour unchanged
```gherkin
Given the full unit, integration and Docker suites
When they run after the change
Then all pass, including Origin allowlist, the Bearer header with 1 or more spaces, and the createHttpHandler web-standard path (the checks stay in `handle` too)
```
