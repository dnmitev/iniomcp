<objective>
## Goal
Add `create_payment` behind `INIO_ALLOW_WRITES`. It records one payment against an invoice, for a curated set of transaction types.

## Purpose
Clients can record payments and fee waivers from the assistant. The payments API has no idempotency: every resend creates another payment. The tool must therefore never report a failure for a payment that went through, and must tell the model to check before any retry.

## Output
One tool, unit and integration tests, README and CHANGELOG. `reverse_payment` and `create_customer` move to 04-04 (see Decisions).
</objective>

## Decisions (user, 2026-10-29)
- 04-03 is payments only. Creating customers moves to 04-04, together with reversal if it proves usable. Creating invoices is reconsidered in 04-04: POST /invoices sends the invoice to the end customer immediately.
- Transaction types are a curated set: `direct_payment`, `good_will`, `bank`, `reminder_fee_waiver`. The types `credit_loss`, `cancelled` and the others are not offered until asked for.
- `reverse_payment` is deferred. No public read endpoint exposes a `paymentAllocationId` (live check). Whether the payment id from create works as one is unverified and needs a live write probe; see 04-04.

## API facts
- **POST /payments** takes an array. Required: `clientId`, `invoiceNo`, `transactionType`. Optional: `amount`, `paidDate`, `additionalInformation`, `confirmFeeAutoRemoval`, and others not used here.
  - `amount` is a number ≥ 0 (2 decimals by default), or `{ capital?, fee? }` for good_will and direct_payment. It is required for a partial payment and not allowed for a full payment.
  - `paidDate` is YYYY-MM-DD and defaults to today; it may be backdated. `confirmFeeAutoRemoval` allows an escalation fee to be removed before a backdated payment.
  - `additionalInformation` is up to 100 characters.
  - Runs `processPayment`, which may close the invoice. **No idempotency.**
- `clientId` = the token's `inio_client_id` claim.

## AC-1: create_payment input
```gherkin
Given create_payment with number (the invoiceNo, 1–100 characters), transactionType (direct_payment|good_will|bank|reminder_fee_waiver)
  and exactly one of: amount (number > 0, at most 2 decimals) / amount { capital?, fee? } (each ≥ 0, at most 2 decimals, at least one > 0; only for direct_payment and good_will) / fullPayment: true
  and optional paidDate (YYYY-MM-DD), additionalInformation (1–100), confirmFeeAutoRemoval (boolean)
When the input breaks any of these rules (no amount and no fullPayment, both given, a breakdown with another type, zero or negative amount, unknown keys)
Then it is rejected locally with a clear message and no API call is made
```

## AC-2: create_payment request
```gherkin
Given valid input
When it is called
Then POST /payments is sent with [{ clientId: <token inio_client_id>, invoiceNo, transactionType, amount? (absent for fullPayment), paidDate?, additionalInformation?, confirmFeeAutoRemoval? }]
And if the token has no inio_client_id, the tool fails before any POST
```

## AC-3: create_payment result, never fail after a 2xx
```gherkin
Given the POST answers 2xx with [paymentId]
Then the result is { paid: true, invoice, transactionType, amount or fullPayment, paymentId }, plus remainingAmount and paymentStatus read back with GET /invoices/by-number/{n} (a failed read-back gives a note)
And when the 2xx answer cannot be read (including an InioApiError with a 2xx status from the client), the result is success: { paid: true, invoice, note: 'The payment was recorded, but the API answer could not be read. Do not retry; check the invoice first.' }
And a timeout or lost response is an error that says the payment may or may not have been recorded, and to check get_invoice (remainingAmount) before any retry
```

## AC-4: Gate, description, integration, docs

Given INIO_ALLOW_WRITES=true

And the integration suite covers create_payment through the built server (method, path, body including clientId from the test token, audit header, read-back)
And the README write-tools table lists create_payment, and the CHANGELOG has an Unreleased entry
