<objective>
## Goal
Add `create_customer` behind `INIO_ALLOW_WRITES`. It creates one customer per call, and this plan closes Phase 4.

## Purpose
Clients can onboard a customer from the assistant before recording invoices elsewhere. Creating a customer is database-only and reaches no one. A duplicate `customerNo` returns 409, so a retry cannot create the same customer twice.

## Output
One tool, unit and integration tests, README and CHANGELOG. The README states that payment reversal and invoice creation are not available.
</objective>

## Decisions (user, 2026-10-29)
- **reverse_payment is out of v0.1.** The live probe showed that a payment id is not a paymentAllocationId ("Payment allocation was not found!"), and no public endpoint exposes allocation ids.
- **create_invoice is out of v0.1.** It sends the invoice to the end customer immediately and needs full calcInput and workflowsSettings.
- **create_customer accepts SSN, orgNr and vatNo**, validated by customer type. There is no workflowsSettings input; the customer inherits the settings.

## API facts
- **POST /customers** takes an array, all-or-nothing.
  - Required: serviceLineName (1–60), customerName (2–100), languageCode (EN|SV|BG|DE), customerNo (1–50, unique per client), customerType (B|C), customerAddress (countryCode, city, zipCode, addressLine1 required; addressLine2–5 optional), clientId (uuid).
  - Optional: distributionEmailAddress, distributionEmailAddress2, distributionEmailAddress3 (email, ≤150), mobilePhoneNo (^\+\d{1,17}$), shippingAddress (full address), SSN (1–25, C only), orgNr (1–25, B only), vatNo (1–100, B only), plus customerTag1, glnNumber, interestInvoice, directDebit and workflowsSettings, which are not offered.
- The response is 201 with `[customerId]`. A duplicate customerNo returns 409.

## AC-1: create_customer input
```gherkin
Given create_customer with the required fields:
    customerNo, customerName, customerType (B|C), languageCode, serviceLineName, customerAddress (full)
  and optional distribution emails (all different, compared ignoring case), mobilePhoneNo, shippingAddress (full),
    SSN (only when customerType is C), orgNr and vatNo (only when customerType is B)
When the input breaks a rule:
  a missing required field, a partial address, SSN on B, orgNr or vatNo on C, duplicate emails,
  workflowsSettings, clientId, customerTag1 or an unknown key
Then it is rejected locally with a clear message and no API call is made
```

## AC-2: create_customer request and result
```gherkin
Given valid input
When it is called
Then POST /customers is sent with [{ ...input, clientId: <token inio_client_id> }], and fields that were not given are left out
And a 201 with [customerId] gives { created: true, id, customerNo }
And an unreadable 2xx, including an InioApiError with a 2xx status, gives success: { created: true, customerNo, note: 'The customer was created, but the API answer could not be read.' }
And a 409 is an error that says a customer with this customerNo already exists and to use get_customer
And status 0 or ≥ 500 says the customer may or may not have been created; check get_customer by number before retrying
```
