<objective>
## Goal
`node src/index.ts` with the four `INIO_*` env vars starts a stdio MCP server exposing one read-only tool, `get_invoice`, that authenticates with client credentials, calls the Inio API, unwraps the envelope, redacts PII and returns the invoice — all built through `/tdd`.

## Purpose
The thinnest end-to-end slice: every later tool reuses the token provider, API client, error mapping and redaction built here.

## Output
`src/auth.ts`, `src/inio-client.ts`, `src/redact.ts`, `src/logger.ts`, `src/tools/get-invoice.ts`, `src/server.ts`, real `src/index.ts`, unit tests for each.

## Stack notes
- MCP TypeScript SDK **v2** (`@modelcontextprotocol/server` 2.4, `@modelcontextprotocol/client` 2.4 for tests), not the legacy `@modelcontextprotocol/sdk` 1.x.
- Logging with **pino** to stderr (stdout is the stdio protocol channel). OpenTelemetry is deferred to the HTTP mode (Phase 3/5), where a collector is realistic; for a locally spawned stdio server, stderr logs are what MCP clients capture (e.g. Claude Desktop's `mcp-server-*.log`).
</objective>

<acceptance_criteria>

## AC-1: Token provider
```gherkin
Given authUrl, clientId, clientSecret and an injected fetch and clock
When getToken() is called
Then it POSTs application/x-www-form-urlencoded grant_type=client_credentials, client_id, client_secret to authUrl and returns access_token
And repeated calls reuse the cached token until 60 s before expires_in elapses, then fetch a new one
And concurrent calls while a fetch is in flight share one request
And invalidate() forces the next call to fetch
And a non-2xx response throws "Authentication failed (HTTP <status>[: <error>]). Check INIO_CLIENT_ID and INIO_CLIENT_SECRET." using only the OAuth "error" code, never the secret, token or raw body
And a network failure throws "Cannot reach the Inio auth server (INIO_AUTH_URL)."
And a 2xx without a string access_token throws an authentication error
```

## AC-2: API client
```gherkin
Given apiUrl, a token provider and an injected fetch
When get(path) is called
Then it sends GET apiUrl + path with "Authorization: Bearer <token>" and "Accept: application/json"
And on HTTP 401 it invalidates the token and retries exactly once
And on success it returns the envelope's "result"
And on an error envelope it throws InioApiError { status, code, message, correlationId } from the body
And on a non-JSON or unexpected error body it throws InioApiError with status and a generic message
And path segments supplied by callers are URL-encoded
```

## AC-3: PII redaction
```gherkin
Given any JSON value
When redact(value) is applied
Then values of keys IBAN, SSN, bankAccount, accountNumber (case-insensitive, any depth, inside arrays too) become "[redacted]"
And other values and the input object are unchanged (returns a copy)
```

## AC-4: get_invoice tool
```gherkin
Given a registered get_invoice tool (annotations: readOnlyHint true, openWorldHint true)
When called with { id: <uuid> } it calls GET /invoices/{id}
And when called with { number: <invoiceNo> } it calls GET /invoices/by-number/{invoiceNo}
And with both or neither, or a non-uuid id, or extra keys, it returns a validation error without calling the API
And on success it returns the invoice as compact JSON text only (no structuredContent until Phase 2 trimming), redacted unless revealPii is true
And on InioApiError it returns isError: true with "<code>: <message> (correlationId <id>)"
And on an auth failure it returns isError: true with the auth message
```

## AC-5: stdio server
```gherkin
Given valid INIO_* env vars
When `node src/index.ts` starts
Then an MCP client over stdio sees server name "inio-mcp" and exactly one tool, get_invoice
And nothing but protocol messages is written to stdout
Given invalid env vars
When it starts
Then the config error is printed to stderr and the process exits with code 1
```

## AC-6: Logging and token metrics
```gherkin
Given INIO_LOG_LEVEL (default "info"; one of fatal, error, warn, info, debug, trace, silent) — validated by loadConfig
When the server runs
Then all logs are JSON lines on stderr, never stdout
And each tool call logs one line at info: tool, durationMs, outcome (ok | error), upstream status and correlationId when present, responseBytes and approxTokens (ceil(bytes / 4)) of the returned content
And each upstream HTTP call logs at debug: method, path (no query string), status, durationMs
And token fetches log at debug: cache hit/miss and expiry, never the token
And pino redaction removes authorization headers, client_secret, access_token and any key named secret/token/password from logged objects
And startup logs at info: server version, transport, allowWrites, revealPii, log level (never credentials)
```

