<acceptance_criteria>

## AC-1: Toolchain runs clean
```gherkin
Given a fresh clone with Node 24 and corepack
When `yarn install --immutable && yarn lint && yarn typecheck && yarn test && yarn build` runs
Then every command exits 0
```

## AC-2: Config validation
```gherkin
Given environment variables
When `loadConfig(env)` is called
Then it returns a typed config when INIO_CLIENT_ID, INIO_CLIENT_SECRET, INIO_AUTH_URL, INIO_URL are present and valid
And it throws one error listing every missing or invalid variable
And INIO_URL / INIO_AUTH_URL with http:// are rejected unless the host is localhost, 127.0.0.1 or [::1]
And an issuer-style INIO_AUTH_URL gets "/protocol/openid-connect/token" appended; a URL already ending in "/token" is kept
And INIO_URL trailing slashes are trimmed
And INIO_ALLOW_WRITES / INIO_REVEAL_PII default to false and accept only "true"/"false"
And MCP_TRANSPORT defaults to "stdio" and accepts only "stdio"/"http"
And the client secret never appears in any thrown error message
```

## AC-3: Mutation gate
```gherkin
Given the unit tests for src/config.ts
When `yarn mutation` runs
Then the Stryker mutation score is at least 80 (break threshold) and the run fails below it
```

## AC-4: CI gates every PR
```gherkin
Given a pull request or push to main on GitHub
When the ci.yml workflow runs
Then lint, typecheck, unit tests, Stryker (incremental, break 80) and build run, and any failure fails the workflow
And the workflow uses no repository secrets
```

## AC-5: TDD agent team works end to end
```gherkin
Given .claude/agents/* and .claude/commands/tdd.md
When `/tdd` is run for the config story
Then senior-qa-automation writes failing tests first (only under test/)
And senior-developer makes them pass (only under src/)
And reviewer approves or returns findings
And mutation-tester runs Stryker on changed files and returns surviving mutants as challenges until the score is at least 90 or the remaining survivors are justified as equivalent
```

<task type="auto">
  <name>Task 2: TDD agent team and /tdd command</name>
  <files>.claude/agents/senior-qa-automation.md, .claude/agents/senior-developer.md, .claude/agents/reviewer.md, .claude/agents/mutation-tester.md, .claude/commands/tdd.md</files>
  <action>
    Agents (Claude Code subagent markdown with frontmatter name/description/tools):
    - senior-qa-automation: input = story + acceptance criteria; writes failing tests under test/ only; must run tests and show they fail for the right reason; never edits src/.
    - senior-developer: makes failing tests pass with the minimum code under src/ only, then refactors with tests green; never edits test/; runs lint + typecheck + tests.
    - reviewer: read-only; reviews the diff for correctness, security (secret leakage, PII, https enforcement, write gating), simplicity and test quality; outputs APPROVE or a numbered findings list with file:line.
    - mutation-tester: adversary; runs `yarn mutation --mutate <changed src files>`; reports each surviving mutant (file:line, mutator, original → mutated) as a challenge and proposes the behavior a test should pin; may flag equivalent mutants with reasoning; never edits src/; does not write the killing tests itself (QA does).
    Command `/tdd <story>`: orchestrates QA (red) → developer (green/refactor) → reviewer → mutation-tester; loops back to QA with challenges while score on changed files is below 90 (max 3 rounds), then to developer if reviewer blocks; ends with a summary: tests added, score, findings resolved.
  </action>
  <verify>Files have valid frontmatter; `/tdd` appears in Claude Code command list; agents listed by `/agents`</verify>
  <done>AC-5 structure in place (exercised in Task 3)</done>
</task>
