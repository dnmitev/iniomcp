<objective>
## Goal
Prove the built server works end to end over real HTTP and a real OIDC server: a spawned `node dist/index.js` (stdio) obtains a token from a Keycloak container, calls a fake Inio API over HTTP, and answers `get_invoice`. Add an opt-in live suite for the test environment, and confirm it in Claude Desktop.

## Purpose
Unit tests use fake fetch. This plan catches what fakes hide: form encoding and client authentication accepted by real Keycloak, token expiry handling with real `expires_in`, Node's real fetch, the built `dist/` bin, stdio framing, and the real API's response shape.

## Output
Integration suite (`npm run test:integration`), live suite (`npm run test:live`, skipped unless configured), CI job for integration tests, README install snippet for Claude Desktop, and a verified Claude Desktop session.
</objective>

<acceptance_criteria>

## AC-1: Real token flow
```gherkin
Given a Keycloak container (pinned version) with an imported realm that has a confidential client with service accounts enabled
When the spawned server handles get_invoice
Then it obtains an access token from Keycloak's real token endpoint (both token-endpoint and realm-issuer forms of INIO_AUTH_URL work)
And the fake API receives "Authorization: Bearer <a JWT issued by that realm>"
And wrong client credentials produce the tool error "Authentication failed (HTTP 401: <OAuth error code from the server, unauthorized_client on Keycloak 26.8>). Check INIO_CLIENT_ID and INIO_CLIENT_SECRET."
```

## AC-2: Built server over stdio, real HTTP
```gherkin
Given `npm run build` output and a fake Inio API (node:http) serving the real single-envelope shape
When an SDK client spawns `node dist/index.js` and calls get_invoice by id and by number
Then it receives the redacted invoice JSON
And a 404 from the API yields "NOT_FOUND: … (correlationId …)"
And an unreachable API yields "NETWORK_ERROR: Cannot reach the Inio API (INIO_URL)."
And stderr contains only JSON log lines and never the client secret or access token
```

## AC-3: Fixture fidelity
```gherkin
Given the field set of a real invoice from the test environment
When the fixture test/integration/fixtures/invoice.json is created
Then it has the same keys and nesting as the real response, with synthetic values only (no real names, emails, IBANs, URLs or IDs)
```

## AC-4: Opt-in live suite
```gherkin
Given INIO_LIVE=1 and INIO_CLIENT_ID, INIO_CLIENT_SECRET, INIO_AUTH_URL, INIO_URL (and optional INIO_LIVE_INVOICE_NUMBER) in the environment or a local .env
When `npm run test:live` runs
Then it spawns the server against the live environment, looks up an invoice (first one from the list endpoint if no number is given), and asserts a redacted, non-envelope invoice and a NOT_FOUND for an unknown number
And without INIO_LIVE=1 the suite is skipped and exits 0
And no credentials or invoice data are written to test output
```

## AC-5: CI
```gherkin
Given a pull request
When CI runs
Then the integration suite runs in its own job on ubuntu-latest (Docker available) after build, with no secrets
And the live suite never runs in CI (release workflow comes in Phase 3)
```

```gherkin
Given the README snippet and the four env vars for the test environment
When the user adds the server to Claude Desktop and asks for an invoice by number
Then Claude calls get_invoice and answers with the invoice, with PII redacted
```

<task type="checkpoint:decision" gate="blocking">
  <decision>Mock for the Inio API in integration tests</decision>
  <context>The spec has no response examples, and its 200 schemas nest the envelope several times (`result.oneOf → {success, status, result: …}`), while the live API returns one envelope (verified in 01-02). A schema-driven mock would therefore return the wrong shape.</context>
  <options>
    <option id="fake-api">
      <name>Small node:http fake API + sanitized fixture (recommended)</name>
      <pros>Matches the real response shape; no extra container; fast; full control of 404/500/latency cases</pros>
      <cons>Does not validate our requests against the spec; fixture can drift (covered by the live suite)</cons>
    </option>
    <option id="prism">
      <name>Prism mock from openapi/inio.json</name>
      <pros>Validates request paths and params against the spec</pros>
      <cons>Returns nested envelopes unless the spec copy is fixed; extra image; tests would assert behavior that differs from the real API</cons>
    </option>
  </options>
  <resume-signal>Select: fake-api or prism</resume-signal>
</task>
