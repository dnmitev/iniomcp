## AC-1: Chart published by the release workflow
```gherkin
Given a v* tag on main that passed verify
When the release workflow runs
Then a `chart` job (permissions contents: read, packages: write; pinned setup-helm) packages charts/inio-mcp with version and appVersion from the tag, skips if that chart version already exists in GHCR, and pushes to oci://ghcr.io/dnmitev/charts
And the GitHub Release job waits for it
And devops-reviewer approves the change
```

## AC-2: 0.5.0 prepared and guarded
```gherkin
Given the release commit
When tests run
Then package.json, package-lock.json and Chart.yaml say 0.5.0, every package/image pin and every chart `--version` / `targetRevision` in README and docs is 0.5.0 (docs test extended to chart pins), and CHANGELOG has a dated [0.5.0] section summarising Phases 8-11
```

## AC-3: Released
```gherkin
Given the PR merged and tag v0.5.0 pushed on the merge commit, and the owner approved the release environment
When the workflow finishes
Then npm latest = 0.5.0 with provenance, GHCR has 0.5.0/0.5/latest (multi-arch, smoke test passed before push), the chart 0.5.0 is pullable with `helm pull oci://ghcr.io/dnmitev/charts/inio-mcp --version 0.5.0`, and the GitHub Release exists
And the GHCR chart package is public (owner sets visibility if GitHub created it private)
```

## AC-4: Running on EKS
```gherkin
Given the owner's ArgoCD and infra repo
When the owner applies the Application with the values Claude provides (ingress-nginx host, existingSecret)
Then the pods are Ready and a client with the token gets the tool list at https://<host>/mcp
```
