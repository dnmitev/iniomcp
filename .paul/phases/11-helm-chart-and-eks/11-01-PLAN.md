<objective>
## Goal
A Helm chart at `charts/inio-mcp/` that runs the existing image in HTTP mode on Kubernetes, with an optional ingress-nginx Ingress and an optional Gateway API HTTPRoute side by side, secrets from an existing Secret, and a restricted security context. CI lints it, validates three render variants against Kubernetes and Gateway API schemas, and installs it on kind for a 401/200 smoke test.

## Purpose
The team runs inio-mcp on EKS through ArgoCD (design input `.paul/research/v0.3-helm-chart.md`). Publishing and the 0.5.0 release follow in 11-02.

## Output
- Chart (Deployment, Service, optional Ingress, optional HTTPRoute, optional Secret, NOTES)
- `ci/` values files for the three variants (ingress, httproute, both)
- CI job `chart`: helm lint, helm template + kubeconform ×3, kind install + smoke
- docs/hosting.md "Kubernetes (Helm)" section; chart README
- Test: Chart.yaml `version` and `appVersion` equal package.json
</objective>

<acceptance_criteria>

## AC-1: Chart runs the HTTP server safely
```gherkin
Given `helm install` with `existingSecret` naming a Secret that holds INIO_CLIENT_SECRET and MCP_AUTH_TOKEN, plus INIO_URL, INIO_AUTH_URL and INIO_CLIENT_ID in values
When it renders
Then the Deployment (2 replicas by default) runs the image (tag defaults to appVersion; optional digest) with MCP_TRANSPORT=http and HOST=0.0.0.0 fixed
And optional settings (INIO_ALLOW_WRITES, INIO_WRITE_TOOLS, INIO_MAX_PAYMENT_AMOUNT, INIO_REVEAL_PII, INIO_LOG_LEVEL, INIO_REQUEST_TIMEOUT_MS) are set only when given
And MCP_ALLOWED_ORIGINS defaults to https://<ingress.host> and https://<each httpRoute hostname> when those are enabled, overridable
And secrets come only from the Secret (envFrom secretKeyRef), never from plain values
And the pod runs as non-root with readOnlyRootFilesystem, all capabilities dropped, no privilege escalation, seccomp RuntimeDefault, automountServiceAccountToken false
And liveness/readiness are tcpSocket on 3000, with a small preStop sleep before SIGTERM
And rendering fails with a clear message when neither existingSecret nor secret.create is set
```

## AC-2: Ingress and Gateway API side by side
```gherkin
Given ingress.enabled and/or httpRoute.enabled
When rendered
Then the Ingress uses className, host, tls and annotations from values (README documents the ingress-nginx annotations: body size 256k, read/send timeout 120, buffering off)
And the HTTPRoute (gateway.networking.k8s.io/v1) uses parentRefs, hostnames, PathPrefix /mcp and optional timeouts.request
And both can be enabled at once, pointing at the same Service
```

## AC-3: Validated in CI
```gherkin
Given a PR
When the `chart` CI job runs
Then helm lint passes; helm template for ci/ingress, ci/httproute and ci/both validates with kubeconform (strict, Kubernetes schemas plus the Gateway API CRD schema)
And a kind cluster installs the chart (image tag overridden to the published 0.4.0, a test Secret) and a curl through port-forward gets 401 without the token and 200 for initialize with it
And every action and downloaded binary is pinned (SHA or version + checksum)
```

## AC-4: Documented and version-guarded
```gherkin
Given docs/hosting.md and charts/inio-mcp/README.md
When read
Then they show install from the OCI chart (available from 0.5.0), an ArgoCD Application example, a Secret example (hand-made and External Secrets Operator), the ingress-nginx and Gateway API values, and a note on Reloader or a restart after rotating the Secret
And a unit test fails when Chart.yaml version or appVersion differs from package.json
```
