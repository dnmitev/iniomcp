<objective>
## Goal
Admins can narrow which write tools exist (`INIO_WRITE_TOOLS`) and cap a single payment (`INIO_MAX_PAYMENT_AMOUNT`). Both are off by default, so nothing changes unless set. Write tool descriptions say what happens later, not just now (trimmed AEGIS R3: parts a, b, d, e).

## Purpose
A team server that only needs to pause reminders should not also be able to record payments, and a typo in an amount should not post a huge payment. Ease of use stays first: defaults are unchanged.

## Output
- `src/config.ts`: `writeTools` (list or all) and `maxPaymentAmount` (number or none), validated
- `src/server.ts`: write tools registered from a name→register map, filtered by the allowlist
- `src/tools/create-payment.ts`: ceiling check before the POST
- Later-effect sentences in four write tool descriptions
- README variables table, Write tools section ("don't always-allow write tools"), hosting guide note
</objective>

<acceptance_criteria>

## AC-1: Write-tool allowlist
```gherkin
Given INIO_ALLOW_WRITES=true and INIO_WRITE_TOOLS unset or empty
When the server starts
Then all 11 write tools are registered, as today

Given INIO_ALLOW_WRITES=true and INIO_WRITE_TOOLS="create_customer_pause, cancel_customer_pause"
When the server lists its tools
Then the 7 read tools and only those two write tools are registered (names trimmed, case-sensitive)

Given INIO_WRITE_TOOLS names an unknown tool or a read tool
When the config loads
Then startup fails listing the unknown names and the valid write tool names

Given INIO_WRITE_TOOLS is set but INIO_ALLOW_WRITES is not true
When the config loads
Then startup fails with "INIO_WRITE_TOOLS needs INIO_ALLOW_WRITES=true"
```

## AC-2: Payment ceiling
```gherkin
Given INIO_MAX_PAYMENT_AMOUNT is unset
When create_payment is called
Then behaviour is unchanged (no extra API call)

Given INIO_MAX_PAYMENT_AMOUNT=500
When create_payment is called with amount 600, or {capital, fee} summing to more than 500
Then it fails before any POST with a message naming the ceiling, and nothing is recorded

Given INIO_MAX_PAYMENT_AMOUNT=500 and fullPayment true
When the invoice's remainingAmount (read with GET first) is above 500, or cannot be read
Then it fails before any POST, saying to pass an explicit amount within the ceiling
And when remainingAmount is 500 or less the payment proceeds as today

Given INIO_MAX_PAYMENT_AMOUNT is not a positive number with at most 2 decimals
When the config loads
Then startup fails naming the variable
```

## AC-3: Later effects in descriptions
```gherkin
Given the write tool descriptions
When an assistant reads them
Then cancel_customer_pause says reminders and debt-collection steps resume on their normal schedule
And update_invoice_stop_until_dates says clearing a date lets held-back steps run on their next schedule
And update_customer says future invoices and reminders go to the new distribution addresses
And reset_invoice_stage says the reminder and fee schedule restarts from the new stage
```

## AC-4: Documented
```gherkin
Given the README and hosting guide
When an admin reads them
Then INIO_WRITE_TOOLS and INIO_MAX_PAYMENT_AMOUNT are in the variables table with defaults and examples
And the Write tools section advises against permanently allowing (auto-approving) write tools in any client
And docs/hosting.md suggests both settings for a team server
```
