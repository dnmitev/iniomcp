<objective>
## Goal
Every write leaves a log line saying which tool changed what (target identifiers), with which outcome, from which MCP client. Rejected HTTP requests and transport errors become visible. AEGIS R8 (F-05-004, F-04-003), plus two deferred items on the same files.

## Purpose
An integration layer that changes money and customer data needs an audit trail on the server side, not only Inio's `inio-mcp` audit field. It is also the base for per-user attribution in v0.4.

## Output
- `withToolLogging` logs `target` (identifiers from the arguments) and `client` (MCP clientInfo name/version) for write tools
- startup log includes the write allowlist and payment ceiling
- `http.ts`: 401s logged at warn with remote address, at most once per minute plus a suppressed count; MCP handler errors logged at warn
- `acceptedUnreadable` can name what to check; create_customer_pause passes the customer
- README/hosting: what the logs contain; fixed-token HTTP has no per-person attribution
</objective>

<acceptance_criteria>

## AC-1: Write calls are attributed in the log
```gherkin
Given a write tool call (any of the 11)
When it finishes, ok or error
Then the existing "tool call" info line also carries `write: true`, `target` (only identifier fields present in the arguments: id, number, customerId, customerNo, pauseId, invoiceNo) and `client` (MCP clientInfo name and version, if the client sent them)
And no other argument values (amounts, emails, addresses, SSN, free text) are logged
And read tool lines are unchanged except for `client`
```

## AC-2: Startup states the write policy
```gherkin
Given the server starts
When the "server started" line is logged
Then it includes writeTools (the registered write tool names, or none) and maxPaymentAmount when set
```

## AC-3: Rejected HTTP requests are visible but bounded
```gherkin
Given HTTP mode
When requests are rejected with 401
Then a warn line "unauthorized request" is logged with the remote address and path, at most once per 60 s; the next line after a quiet period includes how many were suppressed
And the Authorization header value is never logged
And 404s are not logged
```

## AC-4: Transport errors are logged
```gherkin
Given HTTP mode
When the MCP handler reports an error (the SDK's onerror or equivalent hook)
Then it is logged at warn with the error message, without request bodies
```

## AC-5: Unreadable writes name what to check
```gherkin
Given create_customer_pause's POST succeeds but the answer cannot be read
When the tool returns the accepted-unreadable result
Then the text names the customer to check (its id), and other tools that pass nothing keep today's text
```

## AC-6: Documented
```gherkin
Given the README Logs section and docs/hosting.md
When read
Then they say write calls are logged with tool, target identifiers, outcome and MCP client name; that a shared fixed-token server cannot tell people apart (everyone appears as the same client); and that 401s are logged with the remote address
```
