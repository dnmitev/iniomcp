<objective>
## Goal
Add the shared pieces every read tool needs: query parameters on the client, a pagination contract, and compact results with empty values removed. Then ship `list_customers` and `get_customer` on top of them, and move `get_invoice` onto the same helpers.

## Purpose
Clients can start exploring customers from the assistant. The helpers set the pattern that 02-02 copies for invoices, pauses and retry attempts, so it is decided once here.

## Output
`client.get` with query and headers, `src/tools/result.ts` (result, error, compact and pagination helpers), two new tools, `get_invoice` refactored and smaller, unit tests, and live suite cases for both customer tools.
</objective>

## Live API facts (checked 2026-10-28, test environment)
- `GET /customers?limit&offset` returns `result: { data: Customer[], limit, offset, total }`, about 1 KB per item. Filters in the spec: `customerNo`, `directDebit`, `serviceLineId`, `sort`, `order`.
- `GET /customers/{id}` and `/customers/by-number/{customerNo}` return `result: { externalCustomer, serviceLine, effectivePause }`, about 5 KB. Most of that is `externalCustomer.workflowsSettings` and nulls.
- Customer fields: id, customerNo, customerName, customerType, serviceLineName, languageCode, directDebit, orgNr, vatNo, SSN, distribution emails, mobilePhoneNo, customerAddress, shippingAddress, metadata, workflowsSettings, createdAt, updatedAt, deletedAt.

<acceptance_criteria>

## AC-1: Query parameters and headers on the client
```gherkin
Given client.get(path, { query: { limit: 25, offset: 0, customerNo: undefined, directDebit: false }, headers: { 'x-customer-no': 'C-1' } })
When the request is sent
Then the URL is path + "?limit=25&offset=0&directDebit=false" (undefined values dropped, values URL-encoded)
And the extra headers are sent alongside authorization and accept
And debug and warn log lines carry the path without the query string
And existing get(path) calls behave exactly as before
```

## AC-2: Compact results
```gherkin
Given a payload containing null, undefined, "", [] and {} values at any depth
When a tool formats its result
Then those keys and array entries are removed (false and 0 are kept)
And compaction runs before redaction, so a null SSN disappears instead of showing "[redacted]"
And get_invoice uses the shared result helpers, keeps its current error texts, and its live response is smaller than before (bytes logged)
```

## AC-3: Pagination contract
```gherkin
Given a list tool input
Then limit is an integer 1–100 defaulting to 25 and offset is an integer ≥ 0 defaulting to 0 (strict, unknown keys rejected)
When the API returns { data, limit, offset, total }
Then the tool returns { items, total, limit, offset } plus nextOffset = offset + items.length when that is below total
And a payload without a data array yields "UPSTREAM_ERROR: Unexpected list payload from the Inio API."
```

## AC-4: list_customers
```gherkin
Given list_customers with optional customerNo (1–50 chars), directDebit (boolean), limit, offset
When it is called
Then it calls GET /customers with only the provided filters plus limit and offset
And each item contains only id, customerNo, customerName, customerType, serviceLineName, directDebit, orgNr, createdAt (compacted, then redacted)
And it is annotated readOnlyHint and openWorldHint, and logged through withToolLogging
```

## AC-5: get_customer
```gherkin
Given get_customer with exactly one of id (UUID) or number
When it is called
Then it calls GET /customers/{id} or /customers/by-number/{number}
And returns { customer, serviceLine, effectivePause } from the payload, compacted then redacted (redaction skipped when INIO_REVEAL_PII=true)
And it returns NOT_FOUND / NETWORK_ERROR / "Provide exactly one of id or number." exactly like get_invoice
```

## AC-6: Server and live suite
```gherkin
Given the built server
When a client lists tools
Then it sees get_invoice, get_customer and list_customers
And with INIO_LIVE=1, the live suite lists customers (limit 2), fetches the first one by id and by number, and asserts summary-only items, a compact customer, and redacted PII
```
