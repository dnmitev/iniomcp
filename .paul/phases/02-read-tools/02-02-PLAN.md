## Live API facts (test environment, 2026-10-28)
- `GET /invoices`: `{ data, limit, offset, total }`, about 9 KB per item with 47 fields.
- `status=open` (single value or comma-separated) returns **500**. A repeated key works: `status=open&status=open` and `status=cancelled&status=closed` both return 200 with an IN filter. The same applies to `stage`.
- `paymentStatus=notPaid,partiallyPaid` (comma-separated) and repeated keys both work.
- `customerId=<uuid>` and `customerNo=<no>` work as query filters, so the `x-customer-*` headers are not needed. `invoiceNo` is an exact match.
- Sort `invoiceNo`, `invoiceDate`, `dueDate`, `totalAmount`, `remainingAmount`, `createdAt` work; `sort=bogus` and `order=sideways` return 500.
- `GET /invoices/{id}/with-inherited` adds `IBAN`, `bankName`, `bankType`, `feeApplicationDate`, `escalationFeeItemIds`, `effectivePause` (about 10 KB). There is no by-number variant.
- Retry attempts: `{ data: [{ timestamp, errorMessage?, retryReason }], totalItems, failedPaymentCount, successfullAtemptsCount, directDebitEligible }`. `page` has no effect (same items on every page), so only `limit` is exposed. No test invoice has attempts; ineligible invoices return an empty list.
- Pauses: bare array `[{ id, customerId, scope, startAt, endAt, status, reason, createdBy, temporalWorkflowId, createdAt, updatedAt }]`. `status` takes a single value from `scheduled|active|completed|cancelled`; anything else returns 400. No paging.

## AC-1: Repeated query values
```gherkin
Given client.get(path, { query: { status: ['open', 'paused'], limit: 25 } })
When the request is sent
Then the URL is path + "?status=open&status=paused&limit=25" (each array element appended, undefined and empty arrays skipped)
And scalar values behave exactly as in 02-01
```

## AC-2: list_invoices
```gherkin
Given list_invoices with optional invoiceNo, customerId (UUID) or customerNo (not both), status (1–4 of open|paused|cancelled|closed), paymentStatus (1–5 of notPaid|paid|overPaid|partiallyPaid|capitalPaid), sort (invoiceNo|invoiceDate|dueDate|totalAmount|remainingAmount|createdAt|updatedAt), order (asc|desc, requires sort), limit, offset
When it is called
Then it calls GET /invoices with only the provided filters plus limit and offset
And status and paymentStatus are sent as repeated keys; a single status value is sent twice (status=open&status=open) to avoid the API's 500 on a single value
And each item contains only id, invoiceNo, customerNo, invoiceDate, dueDate, currency, totalAmount, remainingAmount, status, stage, paymentStatus (compacted, then redacted)
And customerId together with customerNo is rejected with "Provide at most one of customerId or customerNo."
```

## AC-3: get_invoice withInherited
```gherkin
Given get_invoice with withInherited: true
When called with an id
Then it calls GET /invoices/{id}/with-inherited
When called with a number
Then it calls GET /invoices/by-number/{number}, then GET /invoices/{id}/with-inherited with the id from the first response
And without withInherited (default false) behavior is unchanged
And a first response without a string id yields "UPSTREAM_ERROR: Unexpected invoice payload from the Inio API."
```

## AC-4: get_invoice_retry_attempts
```gherkin
Given get_invoice_retry_attempts with exactly one of id (UUID) or number, and limit 1–50 (default 10)
When it is called
Then it calls GET /invoices/{id}/retry-attempts or /invoices/by-number/{number}/retry-attempts with ?limit only (never page)
And returns { attempts, failedPaymentCount, successfulAttemptsCount, directDebitEligible } (the API's misspelled successfullAtemptsCount mapped; totalItems dropped because it is the page length)
And a payload without a data array yields "UPSTREAM_ERROR: Unexpected retry attempts payload from the Inio API."
```

## AC-5: Customer pause tools
```gherkin
Given list_customer_pauses with customerId (UUID) and optional status (scheduled|active|completed|cancelled)
When it is called
Then it calls GET /customers/{customerId}/pauses with ?status only when given, and returns { pauses: [...] } with temporalWorkflowId removed from each pause
Given get_customer_pause with customerId and pauseId (UUIDs)
When it is called
Then it calls GET /customers/{customerId}/pauses/{pauseId} and returns the pause without temporalWorkflowId
And both compact then redact, use the shared error texts, and a non-array / non-object payload yields "UPSTREAM_ERROR: Unexpected pause payload from the Inio API."
```

## AC-6: Server, metadata and live suite
```gherkin
Given the built server
Then it lists get_customer, get_customer_pause, get_invoice, get_invoice_retry_attempts, list_customer_pauses, list_customers, list_invoices
And every tool's title and input descriptions are pinned in server.test.ts
And with INIO_LIVE=1 the live suite lists invoices (limit 2, status open), fetches one with withInherited by number, gets its retry attempts, and lists pauses for its customer, asserting shape and redaction only
```
