Decisions on the three deferred 05-01 items:
- **Body-size limit:** already handled. The SDK's createMcpHandler answers 413 above DEFAULT_MAX_REQUEST_BODY_SIZE (4 MB). Nothing to build; the README says it in one line.
- **Health endpoint:** skipped (YAGNI). Orchestrators can use a TCP check, and an unauthenticated route would weaken "no unauthenticated endpoint". Add one if someone asks.
- **Graceful shutdown:** built. Node as PID 1 in a container ignores SIGTERM, so `docker stop` waits 10 s and then sends SIGKILL. In HTTP mode, SIGTERM/SIGINT call `close()` and exit 0.

Release flow, as for 0.2.0 (PR #31): version-bump PR → merge → push tag `vX.Y.Z` → release.yml runs the live gate in the protected `release` environment, which the user approves, then npm, GHCR and the GitHub Release.

Branching: 05-01 is PR #32 and not merged yet. Work on `plan/05-02-docker-http`, branched from `plan/05-01-http-transport`, and rebase onto main once #32 merges.

<acceptance_criteria>

## AC-1: HTTP mode shuts down cleanly
```gherkin
Given the server running with MCP_TRANSPORT=http
When the process receives SIGTERM or SIGINT
Then it stops accepting connections, closes open ones, logs "server stopped" at info and exits with code 0 within 2 s
Given the server running over stdio
Then its shutdown behaviour is unchanged
```

## AC-2: The Docker image serves HTTP when configured
```gherkin
Given the image run with MCP_TRANSPORT=http, MCP_AUTH_TOKEN and -p 3000:3000
When a client on the host POSTs to http://127.0.0.1:3000/mcp without a token
Then it gets 401
  And an MCP client with the bearer header lists the 7 read tools
  And `docker stop` completes in under 5 s with exit code 0
Given the image run without MCP_TRANSPORT
Then it still runs the stdio server exactly as before (existing docker tests pass)
```
The image sets `HOST=0.0.0.0` and `EXPOSE 3000`. The token is still required, because the config refuses to start HTTP mode without one.

## AC-3: Operators and clients can set it up from the README
```gherkin
Given a reader of the README
Then the configuration table documents:
  - MCP_TRANSPORT (stdio | http)
  - MCP_AUTH_TOKEN (required for http; ≥32 chars, no whitespace; generate with `openssl rand -hex 32`)
  - PORT, HOST
  - MCP_ALLOWED_ORIGINS (matched by hostname)
  And a "Shared HTTP server" section shows:
    - starting with npx and with Docker;
    - client config for Claude Code (`claude mcp add --transport http … --header`), Cursor (`url` + `headers`) and VS Code (`type: http`, `headers` with an `${input:…}` prompt for the token);
    - security notes: put TLS on a reverse proxy, never expose port 3000 directly; one instance = one tenant; INIO_ALLOW_WRITES and INIO_REVEAL_PII apply to everyone holding the token; rotating the token means a restart; requests over 4 MB get 413
  And the Docker examples use the `:0.3` tag
  And CHANGELOG has a [0.3.0] entry
```

## AC-4: 0.3.0 is released
```gherkin
Given PR #32 and the 05-02 PR merged to main
When tag v0.3.0 is pushed and the release environment is approved
Then npm latest is 0.3.0 with provenance, GHCR has 0.3.0/0.3/latest for amd64 and arm64, and a GitHub Release v0.3.0 exists
  And `npx -y @dnmitev/inio-mcp@0.3.0` with MCP_TRANSPORT=http on a clean machine answers 401 without a token
```
