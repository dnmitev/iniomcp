<objective>
## Goal
`MCP_TRANSPORT=http` starts a Streamable HTTP server on `/mcp`. Every request needs `Authorization: Bearer <MCP_AUTH_TOKEN>`, and a request with a foreign browser `Origin` is refused. The server will not start in HTTP mode without a strong token.

## Purpose
A team can share one instance for one Inio tenant without each member holding the Inio client secret. The secret stays on the server; members hold only the MCP token. There is never an unauthenticated HTTP endpoint (PROJECT.md decision).

## Output
Config for HTTP, a Node HTTP entry built on the SDK's `createMcpHandler` and `toNodeHandler`, unit tests and one end-to-end HTTP integration test. Docker, README, CHANGELOG and the release are in 05-02.
</objective>

Research (2026-10-30, SDK 2.4.0, spec 2026-07-28). Paths are under node_modules/@modelcontextprotocol/server/dist/:
- `createMcpHandler(factory, opts)` (createMcpHandler-*.d.mts:451-495) builds a fresh McpServer per request. Its factory gets `{ era, authInfo, requestInfo }`. Keep the default `legacy` fallback so 2025-era clients still connect. It uses web-standard Request/Response and does no auth or Origin checks itself.
- `toNodeHandler` comes from `@modelcontextprotocol/node` 2.1.2. Its peer is server ^2.4.0, and it pulls in hono and @hono/node-server. The user approved adding it.
- Auth helpers in the root export: `requireBearerAuth`, `verifyBearerToken`, `bearerAuthChallengeResponse` (index.d.mts:144-176). A verifier must set `expiresAt`, or the token is rejected.
- Origin helpers: `originValidationResponse`, `validateOriginHeader`, `localhostAllowedOrigins` (index.d.mts:339-355). A missing Origin passes; the `null` origin is denied.
- Spec: authorization is optional. Origin MUST be validated (403 when it is present and invalid). Do not pass the client's token upstream; we never do, because the Inio token comes from client_credentials.
- Clients: Claude Code, Claude Desktop connectors, Cursor and VS Code all accept a fixed `Authorization: Bearer` header.

<acceptance_criteria>

## AC-1: HTTP config is validated
```gherkin
Given MCP_TRANSPORT=http
When the config loads
Then MCP_AUTH_TOKEN is required and must be at least 32 characters
  And PORT defaults to 3000 and must be an integer from 1 to 65535
  And HOST defaults to 127.0.0.1
  And MCP_ALLOWED_ORIGINS is an optional comma-separated list of origins, each a valid http(s) origin
  And every error names the variable, never its value
Given MCP_TRANSPORT is unset or stdio
Then none of those variables are required and the stdio behaviour is unchanged
Given MCP_TRANSPORT has any other value
Then the error lists stdio and http
```

## AC-2: No request reaches the MCP server without the token
```gherkin
Given a running HTTP server
When a request to /mcp has no Authorization header, a non-Bearer scheme, or a wrong token
Then it gets 401 with `WWW-Authenticate: Bearer`, and no tool runs and no Inio call is made
  And the token comparison is constant-time
  And neither the expected nor the presented token appears in any log line or response body
When the request has the right token
Then it is served by the MCP handler (initialize, tools/list and tools/call work)
```

## AC-3: Foreign browser origins are refused
```gherkin
Given a request with the right token
When its Origin header is present and is neither a localhost origin nor listed in MCP_ALLOWED_ORIGINS
Then it gets 403 and no tool runs
When the Origin header is absent (non-browser clients)
Then it is served
When the Origin is `null`
Then it gets 403
```

## AC-4: One Inio token is shared across requests
```gherkin
Given createMcpHandler builds a new McpServer per request
When several tool calls arrive over HTTP
Then they share one token provider and one Inio API client, so the Inio token is fetched once and refreshed as before, not once per request
  And INIO_ALLOW_WRITES and INIO_REVEAL_PII behave exactly as on stdio
```

## AC-5: Only /mcp is served
```gherkin
Given a running HTTP server
When a request goes to any other path
Then it gets 404 without running the MCP handler
When the server starts
Then it logs (to stderr) the version, transport http, host, port and the existing flags, never the token
```

<boundaries>

## DO NOT CHANGE
- Tool modules under src/tools/ (behaviour is identical on both transports)
- src/auth.ts, src/inio-client.ts, src/redact.ts
- stdio startup behaviour and its logs
- CI and release workflows, Dockerfile (05-02, with the devops-reviewer)

## SCOPE LIMITS
- One instance serves one Inio tenant (its env credentials). No per-user Inio credentials, no token passthrough.
- No MCP OAuth or protected-resource metadata. With a static token the server is not an OAuth resource server; OAuth is a later phase if asked for.
- One shared token. No named tokens, no hot rotation (rotation means a restart).
- No TLS termination; that belongs to the operator's reverse proxy. The README says so in 05-02.
- No new dependency except @modelcontextprotocol/node.

</boundaries>
