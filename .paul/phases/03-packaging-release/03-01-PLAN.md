<objective>
## Goal
Make the server releasable without releasing it yet. That means:
- a correct npm package (`@dnmitev/inio-mcp` 0.1.0, public, stdio only)
- a small non-root Docker image
- automated smoke tests that install the packed tarball and run the image like a client would
- README snippets for Claude Desktop, Cursor and VS Code
- a changelog
- a security review

## Purpose
03-02 adds the release workflow and publishes. Everything that can be checked before a real publish is checked here, in CI, on every PR.

## Output
Package metadata, a config guard for `MCP_TRANSPORT=http`, a package smoke suite, a Dockerfile with a CI build-and-smoke job, README install sections, CHANGELOG.md, and security review findings fixed or recorded.
</objective>

## Decisions (2026-10-29)
- npm name for 0.1.0: personal scope `@dnmitev/inio-mcp`; move to `@inio` later.
- 0.1.0 is stdio only (npm and Docker). Streamable HTTP and its auth come in Phase 5.
- The live gate in the release workflow uses a protected `release` environment; the user adds the secrets (03-02).

## Current state
- `package.json`: `"private": true`, name `@inio/mcp`, version 0.0.0, bin `inio-mcp` → `dist/index.js` (shebang present), files `["dist"]`. `npm pack` gives 19 files, 16 kB.
- `MCP_TRANSPORT=http` is accepted by config but index.ts always starts stdio, so http is silently ignored.
- Tool listing works without network access (the token is fetched on the first tool call).
</context>

<acceptance_criteria>

## AC-1: Transport guard
```gherkin
Given MCP_TRANSPORT=http
When the server starts
Then it exits 1 and stderr says "MCP_TRANSPORT=http is not supported yet; 0.1.0 runs over stdio only."
And MCP_TRANSPORT unset or "stdio" starts as before, and other values keep the existing validation error
```

## AC-2: npm package
```gherkin
Given package.json
Then name is @dnmitev/inio-mcp, version 0.1.0, not private, publishConfig { access: public, provenance: true }, with description, keywords, repository, homepage, bugs, license Apache-2.0 and engines node >= 24
And the tarball contains dist/**, README.md, LICENSE, NOTICE and CHANGELOG.md, and no src, test, .env, reports or .paul files
When the packed tarball is installed into an empty temporary project
Then its inio-mcp bin with an empty env exits 1 with the config error on stderr and nothing on stdout
And with dummy INIO_* values it answers an MCP tools/list over stdio with the seven read tools
```

## AC-3: Docker image
```gherkin
Given the Dockerfile (multi-stage, node 24 on a pinned slim/alpine tag, production dependencies only, USER node, ENTRYPOINT node dist/index.js)
When it is built
Then the image runs as a non-root user, contains no dev dependencies, src, test or .env, and is under 200 MB
And `docker run -i --rm -e INIO_…` answers tools/list with the seven tools
And CI builds the image and runs that smoke check on every PR (no push)
```

## AC-4: Docs and changelog
```gherkin
Given README.md
Then it has install snippets for Claude Desktop, Cursor and VS Code using `npx -y @dnmitev/inio-mcp`, a Docker variant, and the env var table (incl. INIO_LOG_LEVEL, INIO_REVEAL_PII; MCP_TRANSPORT documented as stdio only)
And CHANGELOG.md (Keep a Changelog format) has a 0.1.0 entry listing the seven tools, redaction, 429 handling and the known upstream workarounds
```

## AC-5: Security review
```gherkin
Given the branch diff and src/
When /security-review runs
Then every finding is fixed (via /tdd) or recorded as a deferred issue with a reason
And npm audit --omit=dev reports no high or critical advisories
```
