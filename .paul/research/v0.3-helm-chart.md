# v0.3 Helm chart: design input

**Date:** 2026-11-02
**Status:** Brainstorm, not yet planned. Stage 1 of hosting (see `v0.4-hosted-auth.md`); no Keycloak dependency.

## Owner environment

- EKS, nginx ingress
- Secrets: static Kubernetes Secrets created by hand today; External Secrets Operator available
- Delivery: ArgoCD (GitOps) from an infrastructure repo

## Chart

- Lives in this repo at `charts/inio-mcp/`; chart version = app version; published as an OCI chart to GHCR (`oci://ghcr.io/dnmitev/charts/inio-mcp`) by `release.yml`.
- ArgoCD Application in the infra repo pins chart version and holds values; this repo only publishes.
- Templates: Deployment (2 replicas), Service (ClusterIP 3000), optional Ingress, optional Secret (tests only).
- Skipped until needed: HPA, PDB, NetworkPolicy, ExternalSecret template.

## Decisions

- **Secrets via `existingSecret` only in production.** Works the same for a hand-made Secret and one created by ESO (the ExternalSecret targets the same name). README shows both. Keys: `INIO_CLIENT_SECRET`, `MCP_AUTH_TOKEN`.
- **Secret rotation:** the chart does not own the Secret, so a checksum annotation cannot trigger a rollout; document Reloader or a manual restart.
- **Probes:** `tcpSocket` on 3000; no health endpoint (keeps "no unauthenticated route").
- **Security context:** runAsNonRoot, readOnlyRootFilesystem (verify with the real image), drop ALL, seccomp RuntimeDefault.
- **Fixed env:** `MCP_TRANSPORT=http`, `HOST=0.0.0.0`. Rest from values. `MCP_ALLOWED_ORIGINS` defaults to the Ingress host.
- **Ingress (nginx):** className and annotations from values; documented defaults:
  - `nginx.ingress.kubernetes.io/proxy-body-size: 256k` (matches the app body cap)
  - `nginx.ingress.kubernetes.io/proxy-read-timeout` / `proxy-send-timeout: "120"` (Streamable HTTP responses)
  - `nginx.ingress.kubernetes.io/proxy-buffering: "off"` (SSE streaming)
- **Shutdown:** small `preStop` sleep before SIGTERM so endpoints drop out before the 500 ms drain.
- **Non-loopback startup warning** fires in every pod; expected, documented.
- **ArgoCD friendliness:** no Helm hooks, no randomly generated values (stable diffs).

## Routing: Ingress and Gateway API side by side

Two independent toggles; both may be on during a cutover (same Service backend).

```yaml
ingress:
  enabled: true            # ingress-nginx today
  className: nginx
  host: mcp.example.com
  tls: { secretName: inio-mcp-tls }
  annotations:             # ingress-nginx defaults documented in README
    nginx.ingress.kubernetes.io/proxy-body-size: 256k
    nginx.ingress.kubernetes.io/proxy-read-timeout: "120"
    nginx.ingress.kubernetes.io/proxy-send-timeout: "120"
    nginx.ingress.kubernetes.io/proxy-buffering: "off"

httpRoute:
  enabled: false           # Gateway API (gateway.networking.k8s.io/v1)
  parentRefs:
    - name: shared-gateway
      namespace: gateway-system
      sectionName: https
  hostnames: [mcp.example.com]
  timeouts: { request: 120s }   # standard HTTPRoute field
  annotations: {}
```

- HTTPRoute matches `PathPrefix /mcp` to the Service; TLS terminates on the Gateway listener (owned by the platform, not this chart).
- Body size and buffering have no core Gateway API field; they are implementation policies (e.g. Envoy Gateway BackendTrafficPolicy, NGINX Gateway Fabric ClientSettingsPolicy). The app already enforces the 256 KiB cap and streams, so none is required; README links the common ones.
- `MCP_ALLOWED_ORIGINS` defaults to `ingress.host` plus `httpRoute.hostnames`.
- Migration path: enable `httpRoute`, point DNS at the Gateway, disable `ingress`. `ingress2gateway` can translate existing ingress-nginx objects on the platform side.

## Testing

- CI: `helm lint`; `helm template` + kubeconform for three value sets (ingress, httpRoute, both), with the Gateway API CRD schemas.
- Smoke: kind install, port-forward to the Service (controller-independent), unauthenticated request returns 401.
- devops-reviewer on the chart and release changes.

## Resolved

- Controller: community ingress-nginx (annotations above). Retired upstream, so keep annotations in values; a later move to Gateway API needs no chart redesign.
- `readOnlyRootFilesystem: true` works with image 0.4.0 (verified 2026-11-02: read-only, ALL caps dropped, no-new-privileges; 401 unauthenticated, 200 initialize, exit 0 on SIGTERM). No emptyDir needed.
